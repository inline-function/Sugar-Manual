# 视图协议 v2（Modifier 链 · 回调实例键 · 新组件）

> 本文件是「渲染层能力差距清单」（docs/渲染层能力差距清单.md）的**协议级应答**：
> 逐条给出 v2 的字段形状、KT 端（DshBridge.kt 运行时壳）与 Kotlin Compose 生成物（SfA @compose）两侧的落地方式。
> 语言侧定义在 SfA 仓 app/*.subl（本仓 app/ 同构同步）。
>
> **总原则**：**看起来像 Compose，实际上是 View** —— API 语义对齐 Compose，
> 在 Android 运行时壳里全部展开成传统 View（LayoutParams / setPadding / CardView / Dialog），
> **不引入 Compose 运行时**；在 @compose 工程里则由编译期生成 Kotlin Compose（真 Compose，仍不解释视图）。

---

## 0. 序列化不变量

| 字段 | 形状 | 说明 |
| --- | --- | --- |
| tag | 字符串 | 视图名（如 Box）或 Modifier 元素名（如 Width） |
| modifiers | **有序数组** | Modifier 链，按源码书写顺序（左→右）；**替代**旧的单对象 modifier |
| modifier | 旧形态（单对象） | 仅向后兼容：只在 modifiers 缺失时读取 |
| 回调字段（onClick 等） | 字符串 key | <构造点id>_<运行时实例序号>（协议 v2 的「回调实例键」） |
| children | 数组 | body 展开后的子视图（由 @view 处理器擦除注入） |
| __ord | Nat | 节点身份（重组定位用，与 recomposion$X$N 同源） |

Modifier 元素形状：{"tag":"<元素名>", "0":…, "1":…}（枚举构造子位置参数 → 数字键），与 v1 一致，
只是现在**可以出现在数组里、一条链多个**。

## 1. Modifier 链

### 1.1 语言侧（SfA app/Modifier.subl）—— t54 定稿

```subl
enum MKind {
    Plain(), FillMaxSize(), WrapContent(), Padding(Nat), Width(Nat), Height(Nat),
    FillWidth(), FractionWidth(Rat), FillHeight(), FractionHeight(Rat),
    Padding4(Nat, Nat, Nat, Nat), PaddingH(Nat), PaddingV(Nat), Weight(Rat),
    Background(Str), Clip(Nat), Alpha(Rat), Flash()
}
```

**修饰符的类型就是 `List[MKind]`**（不再是包一层 struct）：视图字段 `modifier: List[MKind] = emptyList()`，
空链 = 无修饰。链用**同名重载函数**（F# 模块风格，语言没有方法定义）：

```subl
fun width(n: Nat): List[MKind]                    // 起点：width(4)
fun width(m: List[MKind], n: Nat): List[MKind]    // 链项：width(4).height(20)
fun padding4(l: Nat, t: Nat, r: Nat, b: Nat): List[MKind]
fun paddingHV(h: Nat, v: Nat): List[MKind]        // = paddingH(h).paddingV(v)
fun plus(a: List[MKind], b: List[MKind]): List[MKind]   // 链拼接：a 的元素在前
```

> **设计要点（t54 验证）**：
> - 不走 `@view struct Modifier` 包装——视图协议字段直接吃 List；struct 包装反而让编译器
>   把默认值 `Plain()` 解析成 MKind 构造子（checker 对同名 ctor/函数优先 ctor），产生大量类型不符。
> - MKind 里**没有** Plain 函数（ctor 名 clash）、没有 Center（与 core Alignment.Center 冲突；
>   对齐走容器 `contentAlignment` 字段）、没有 `fun size`（与 core `size[T]` 冲突）。
> - KT 端保留对旧单对象 `{tag:"Center"}` 的分支作向后兼容。

### 1.2 JSON

```json
{ "tag": "Box", "__ord": 7,
  "modifiers": [ {"tag":"Width","0":4}, {"tag":"Height","0":20}, {"tag":"FractionHeight","0":0.45} ],
  "children": [ … ] }
```

编译器侧（JsCodeGen）在 layout/androidRecompose 序列化前经 __dshViewTree 规范化：modifier 的值是 List（链）时
改键名为 modifiers（元素按链顺序）；单对象旧形态原样保留。

### 1.3 KT 端顺序应用（DshBridge.applyModifiers）

| 元素 | 运行时（View） | 生成物（Compose） |
| --- | --- | --- |
| Width(n) / Height(n) | layoutParams.width/height = dp2px(n) | .width(n.dp) / .height(n.dp) |
| FillMaxSize() | 双维 MATCH_PARENT | .fillMaxSize() |
| WrapContent() | 双维 WRAP_CONTENT | .wrapContentSize() |
| FillWidth() | 宽 MATCH_PARENT | .fillMaxWidth() |
| FractionWidth(f) | lp.width = 屏宽 × f（FILL_PARENT 分数近似） | .fillMaxWidth(f) |
| FillHeight() | 高 MATCH_PARENT | .fillMaxHeight() |
| FractionHeight(f) | lp.height = 屏高 × f | .fillMaxHeight(f) |
| Padding(n) | 四边 n | .padding(n.dp) |
| Padding4(l,t,r,b) | 四边分别 | .padding(start=l.dp, top=t.dp, end=r.dp, bottom=b.dp) |
| Weight(w) | 父是 LinearLayout → LinearLayout.LayoutParams.weight = w | Row/Column 子级 .weight(w)（生成器走带 weight 的重载，外于作用域也可用） |
| PaddingH(h) / PaddingV(v) | 左右 / 上下内边距 | .padding(horizontal = h.dp) / .padding(vertical = v.dp) |
| Background(c) | setBackgroundColor（主题色名或 #AARRGGBB） | .background(Color(0xAARRGGBB)) |
| Clip(n) | GradientDrawable 圆角背景（cornerRadius = n.dp） | .clip(RoundedCornerShape(n.dp)) |
| Alpha(f) | view.alpha = f | .alpha(f) |
| Flash() | AlphaAnimation(1→0.25) 无限反向（650ms AccelerateDecelerate） | Modifier.flash()（无限 transition 650ms Reverse） |

> Center/Align **不在** MKind 里（与 core `Alignment.Center` 冲突、且对齐语义本属容器）：
> 运行时壳走容器 `contentAlignment` 字段（7 档），KT 端对旧单对象 `{tag:"Center"}` 保留兼容分支。

**顺序语义与 Compose 一致**：后者覆盖前者（Width(4) 后再 FillWidth() → 满宽）；
Padding 与 Background 的先后决定「背景是否含内边距」（运行时壳按顺序即时生效；Compose 由 Modifier 链天然保证）。

**消灭的 bug**：「一个视图只能带一个 Modifier」。现在任何视图都能同时定宽定高、加内边距、加权重、居中。

## 2. 回调实例键（动态列表分辨来源行）

### 2.1 键形状

```
key = <构造点id> "_" <运行时实例序号>
例：Button_onClick_1_7      ← 构造点 Button#1 的第 7 次求值（列表第 7 行）
    FloatingButton_onClick_3_1
```

- 构造点 id = <模块>_<视图名>_<字段名>_<编译期序号>（与 v1 相同）；
- 实例序号由 __dshCb 在运行时自增（**每次求值都新开一个槽位**）。

### 2.2 JS 侧注册表

```js
function __dshCb(base, fn) {
  __dshCb.n = (__dshCb.n || 0) + 1;
  var k = base + "_" + __dshCb.n;
  globalThis["__dshFn_" + k] = fn;
  return k;                 // 字段值 = 这个 key，随视图树 JSON 一起过桥
}
```

### 2.3 KT 端分派

```kotlin
private fun jsCallback(key: String, argJs: String) {
    activity.web.evaluateJavascript(
        "try{ globalThis.__dshFn_" + key + "(" + argJs + "); }catch(e){ console.log(e); }", null)
}
```

**多槽**：注册表按 key 存 N 个闭包，点第 i 行 → 只调用第 i 个闭包 → 闭包捕获的 index 就是来源行。
旧协议（纯编译期 key）同款列表项共用一个槽位、后注册覆盖前注册——**点氟伏沙明却选中帕罗西汀**（差距清单 §6）就此消失。

### 2.4 列表写法（语言侧）

```subl
@composable
fun rowsBody(xs: List[Drug]): Any = when (xs) {
    Nil => Box(modifier = Padding(0)) {}
    is Cons(d, rest) => Box(modifier = Padding4(0, 0, 0, 6)) {
        Button(onClick = { unchecked pickDrug(d.name) }) {      // ← 每个实例独立槽位
            Text(text = d.name)
        }
        rowsBody(rest)
    }
    else => Box(modifier = Padding(0)) {}
}
```

生成物（@compose 工程）里同一段变成 items(drugs) { d -> …… callJs(CB_PICK + "_" + index) }——**任意长度**，
不再源码展开固定 4 行。

## 3. 容器升级

| 字段 | 语言 | 运行时（View） | 生成物（Compose） |
| --- | --- | --- | --- |
| spacing | Nat（dp） | LinearLayout 子视图间补 Space（统一 setMargins） | Arrangement.spacedBy(n.dp) |
| arrangement | "Start"/"Center"/"End"/"SpaceBetween"/"SpaceAround"/"SpaceEvenly" | gravity + Space 分配（SpaceBetween：两端顶满、均分间隙） | Arrangement.SpaceBetween 等 |
| wrap | Bool（流式换行 ≈ FlowRow） | com.google.android.flexbox.FlexboxLayout（material 传递依赖）**或** 自实现 FlowLayout——落 DshBridge 内部，不引新依赖 | FlowRow(spacedBy) |
| onClick | (Any) => Null | 容器 setOnClickListener + clickable=true（可点整块） | Modifier.clickable { callJs(key) } |

Button 升级为**容器**：MaterialButton 只承载外观与点击，body 的**全部子视图**装进按钮内的 LinearLayout（纵向居中）
——不再「只取首个 Text 作文案」，按钮里可以放任意组合。

## 4. 新组件

| 组件 | 语言字段 | 运行时（View） | 生成物（Compose） |
| --- | --- | --- | --- |
| Card | cornerRadius: Nat = 12、elevation: Nat = 1、backgroundColor、onClick、body | CardView（圆角 + cardElevation + 内层 LinearLayout） | Card(shape = RoundedCornerShape(r.dp), elevation = CardDefaults.cardElevation(e.dp)) |
| TextButton | label、enabled、onClick、body | MaterialButton(style = TextButton)（无边框无填充） | TextButton(onClick) { … } |
| Icon | name: Str（add/settings/android:ic_menu_info…） | ImageView + 内置矢量表（与 Icons 同一套名字） | Icon(Icons.Filled.X) |
| AlertDialog | visible、title、confirmText、dismissText、onConfirm、onDismiss、body | AlertDialog.Builder（遮罩 + 可点外部取消） | if (visible) AlertDialog(onDismissRequest, confirmButton, dismissButton, title, text) |
| BottomSheet | visible、onDismiss、body | BottomSheetDialog（底部抽屉 + 遮罩 + 下滑关闭） | if (visible) ModalBottomSheet(onDismissRequest, sheetState) |

弹出层的 visible 是**数据字段**（来自状态槽），不是视图节点的增删——layout 整树差量时弹出层不会被重建，
关闭动画也能跑完。onDismiss 回调照旧走实例键。

## 5. 颜色

1. **#AARRGGBB**：parseColor 先试 Color.parseColor（支持 8 位），失败再补 #；语义色名走主题表。
2. **主题色表**（app/Theme.subl）：primary/onPrimary/primaryContainer/onPrimaryContainer/secondary/surface/…
   语言侧是 Str 常量（fun primary(): Str = "primary"），视图字段写 color = primary()；
   运行时壳查表 → 实色；Compose 生成物查 Palette 常量 → MaterialTheme.colorScheme.primary。
   **换主题只改一处**（运行时 DshTheme / 生成物 Palette.kt）。

## 6. 图表多序列 + 动画最小集

```subl
struct Series(label: Str, color: Str, points: List[Rat])

@view struct Chart(
    kind: Str = "line",
    series: List[Series] = emptyList(),   // 逐序列：颜色 + 图例名 + 采样点
    points: List[Rat] = emptyList(),      // 总浓度主线（渐变填充）
    labels: List[Str] = emptyList(),
    color: Str = "",
    legend: Bool = true,
    badge: Str = "估算",
    modifier: Modifier = Plain(),
    body: () => Null = fun(): Null { null }
)
```

- 运行时：ChartView 自绘——每条序列各自颜色细线、主线粗 + 垂直渐变、图例（色点 + 名）、网格 + 双轴刻度。
- 生成物：Subl_ConcentrationChart(...)（Canvas 同构，见 SfA 壳 gen/ChartView.kt）。
- 动画只有一种：**透明度循环**（运行时 AlphaAnimation(1→0.25, 650ms, Reverse, INFINITE)；Compose Modifier.flash()）。
