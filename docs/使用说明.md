# Sugar-Manual 使用说明

本文档面向**使用者与验收者**：如何编译、验证、打包本应用到 Android 设备，以及首页各区域的功能与数据约定。视图渲染协议（新增视图的 JSON 契约与 KT 渲染分支）见同目录 [视图渲染协议补充.md](视图渲染协议补充.md)。

## 1. 首页布局（MD 风格三段式 + 悬浮按钮）

> **t52 更新（2026-10-27）**：首页已改为照 Kotlin Compose 参考实现（F:\KotlinProject\Sugar Manual）逐屏翻译的版本——预警区为**混排彩色标签流**（仅靠颜色分级：危险红/警告黄/提示绿，无组标题、名称不带权重），记录卡为 **surfaceVariant 底 + 药名左侧 4dp 颜色竖条**（药理类别色），顶栏为薄荷绿 primaryContainer 底 + 文档/药物/设置三按钮，FAB 表单照齐参考的四级校验（未选药/非数字/≤0/超 10000mg）。与 Compose 参考实现的**渲染层能力差距**（圆角 Card、FlowRow 换行、Modifier 链、列表项回调、底部抽屉等）逐条登记于 [渲染层能力差距清单.md](渲染层能力差距清单.md)。

- **顶栏**：标题「语法糖手册」+ 淡色版本副标题「V1.0」；「文档」打开仓库主页（openUrl），「设置」打开应用系统设置页（openSettings）。
- **浓度折线图（填满上半区）**：取 t28 引擎的浓度序列（`pk.seriesValues`），采样 0..48h、步长 4h，共 13 点；视图传 `modifier = Height(屏高 * 45 / 100)`（Chart 的 modifier 现已由 DshBridge buildChart 兑现，见协议补充 §1/§6.1）；T½ 与生物利用度 F 从氟伏沙明资料库首个 pk 条目读取（无资料回退 T½=24h、F=1）。空台账（无服药记录）时展示演示剂量（100mg@0h + 100mg@24h）。
- **预警标签（按等级分三组）**：t28 引擎输出（`adrAlert` + `metabAlert`），触发项按**各自引擎阈值**（ADR 3/5/7、代谢 1/3/5）归级，**绿/黄/红三组**纵向排列，每组一行横向标签流（可横滚）：
  - 危险（3）：红底 #FDECEA / 红字 #B3261E
  - 警告（2）：黄底 #FFF8E1 / 黄字 #B26A00
  - 提示（1）：绿底 #E8F5E9 / 绿字 #2E7D32
  - 空组给「：暂无」占位（演示场景提示组为空）
- **服药记录卡**：每条台账记录渲染一张**全宽背景卡片**（Box(Width(screenWidth()), backgroundColor="#F5F5F5") 背景左右填满整宽 + 内层 Padding(24) 左右内边距），四字段：**药物名称**（16sp 粗体）、**剂量**（紫色粗体 "N mg"）、**给药时间**（fmtTime 的 MM-dd HH:mm）、**给药方式**（按药名从药库首个 pk 条目取 route，无资料回退「口服」）。台账最新在前；无记录时显示占位文案。（圆角为已登记缺口，见协议补充 §6.2。）
- **悬浮按钮「服用药物」→ 页内表单**：点击打开**页内表单面板**（当前协议无 Dialog，见协议补充 §6.3）：
  1. **选择本次服用的药物**：联用药物列表逐个按钮（loadDrugs() 药库 + 氟伏沙明/帕罗西汀演示资料），选中项带 ✓ 前缀与加粗；
  2. **填写服用剂量（mg）**：数字键盘 TextField，onChange 只回写草稿（不重建输入框、不丢焦点）；
  3. **确认记录**：解析草稿（ratOr，空/非法值给 toast 提示且**不关闭面板**）→ 台账头插 DoseRec(药名, 剂量, timeNow()) → 写 storage 键 ledger → **layout(content) 整树差量刷新首页**（曲线/卡片/预警全部更新）并弹 toast；**取消**则丢弃草稿复位并刷新。

## 2. 数据与持久化约定

| 键 | 内容 | 序列化 |
| --- | --- | --- |
| `drugs` | 用户药库（t28） | core/json 数组，每元素一个 Drug |
| `ledger` | 服药台账（本任务新增） | core/json 数组，每元素 `{drug, amount, time}`（time 为 Unix 毫秒字符串） |
| `sm_form` / `sm_pick` / `sm_dose` | 表单状态（t47）：面板开关 / 选中药物下标 / 剂量草稿 | "1"/"0" 字符串、数字字符串、自由文本 |

台账 `time` 字段按 drugs.subl 的 Nat 字段约定编码为 JSON **字符串**（`jsonLit(toStr(...))`），读取侧 `jsonNatField` 经 `parseNat` 还原。不使用分号/管道等手工编码。

## 3. 编译与桌面验证

前置：JDK（任意 17+ JRE 即可跑 CLI 编译）、Node.js。

```powershell
# CWD = 本仓库根目录（模块扫描/处理器按 CWD 相对加载）
java -cp "<主仓库 5 模块 jar>;<kotlin-stdlib.jar>" sugared.functor.MainKt compile app -o app/out.js

# 桌面断言（out.test.js = 在生成码闭包内注入桥 mock + 68 条断言）
node app/out.test.js      # 期望：PASSES=82 FAILS=0，退出码 0
```

断言覆盖（82 条）：
- 生命周期注册与布局桥调用、根视图树；
- 顶栏标题/版本/双按钮、图表 kind/color/13 点序列与**独立公式逐点重算一致**、X 轴刻度、**Chart modifier=Height(屏高45%) 填充断言**；
- 预警分级（危险 3）、三组着色（红/黄/绿 levelBg/levelFg）、三组标题与触发项文案（恶心 8 / CYP2D6 5 / 失眠 6 / 嗜睡 5 / 提示组占位）；
- 悬浮按钮属性（主色/圆角/回调 id 注册）；
- 台账 core/json 往返、48h 滑动窗口换算（超窗过滤、空台账回退演示剂量）、保序去重的最近药品排序、行文本格式；
- **FAB 表单全流程端到端**：FAB 开/关（layout 二次差量刷新）、选药 ✓ 高亮、TextField 草稿回写不重渲染、确认提交（台账写入 + 台账药名/剂量/时间核对 + 卡片四字段 + 全宽/内边距断言 + 曲线 13 点首末值按剂量×生物利用度重算）、非法剂量 toast 且面板保持开、取消复位；
- 文档/设置意图（openUrl）、t28 引擎回归（summaryLine、共享反应权重、酶抑制权重、药代字段、doseEffect 三点）。

## 4. 端到端 APK 构建（-A 注解处理器链路）

前置：`JAVA_HOME` 指向 JDK 17（`F:\jdk-17.0.13.11-hotspot`），sdk-lite 解压目录可访问（`F:\SublimationProject\sublimation for android\sdk-lite`）。

```powershell
$env:JAVA_HOME = 'F:\jdk-17.0.13.11-hotspot'
java -cp "<主仓库 5 模块 jar>;<kotlin-stdlib.jar>" sugared.functor.MainKt compile app -o app/out.js `
  -A appDir="F:\SublimationProject\Sugar-Manual\android-app" `
  -A jsPath="F:\SublimationProject\Sugar-Manual\app\out.js" `
  -A sdkDir="F:\SublimationProject\sublimation for android\sdk-lite" `
  -A outDir="F:\SublimationProject\Sugar-Manual\build-apk"
```

- **-A 选项必须给绝对路径**（否则 E-PROCESSOR-SCRIPT）。
- 处理器（`annotation processer/android.subs`）调用宿主能力 `buildAndroidApk`：
  1. 把 JS 产物拷进 `android-app/app/src/main/assets/app.js`（附加 `__dshBoot()` 引导与 `main()` 调用尾）；
  2. 运行 sdk-lite 的无 Gradle 构建脚本（aapt2 compile/link → d8 → zipalign → apksigner，debug 密钥签名）；
  3. 产物：`<outDir>/app-debug.apk`。
- 验收实况（2026-10-26，t29）：编译 exit=0；APK 5.58MB、804 条 zip 条目、`assets/app.js` 71354 字节，含 `Chart("line"...)`/`FloatingButton(...)` 视图构造、saveLedger/loadLedger 与 storagePut/storageGet 桥调用、顶栏与预警着色字符串；`jarsigner -verify` 通过（jar 已验证）。
- 验收实况（2026-10-27，t47 改版后）：桌面编译 exit=0（main.subl 无错误/警告）、`node app/out.test.js` PASSES=82 FAILS=0；APK 重建见下方 t47 更新条目。

## 5. 已知限制

- 语言的算术表达式**不含乘优先于加的优先级**：`acc + a * b` 会生成 `((acc + a) * b)`（编译器输出 H-ARITH-PRECEDENCE 提示）。涉及混合算术时必须显式括号（本仓库 `pk.concentrationAt` 已加括号修复）。
- `core_collection__distinct` 会**排序**而非保序去重；需要保序去重时手写 fold（见 `ledger.recentDrugs`）。
- 尾随 lambda 体内不能 `var` 声明；ANF 参数阴影；模块扫描不递归——详见 README「已知语言/编译器限制」。
- **@view 结构体内联基元有参数阴影陷阱**：`elementAt(xs, i)` 这类编译期内联实现的函数，被内联时生成 `const i = i` 形式——若调用点的实参变量与形参同名（如 `fun f(drugs, i) = elementAt(drugs, i)`）会触发 TDZ「Cannot access before initialization」。规避：形参改用异名（本仓库 `drugAt(drugs, n)`）。
- 视图协议缺口（不私自扩协议）：Box 无圆角背景（见协议补充 §6.2）、无 Dialog/Dropdown（§6.3 页内表单替代）。
