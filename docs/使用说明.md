# Sugar-Manual 使用说明

本文档面向**使用者与验收者**：如何编译、验证、打包本应用到 Android 设备，以及首页各区域的功能与数据约定。视图渲染协议（新增视图的 JSON 契约与 KT 渲染分支）见同目录 [视图渲染协议补充.md](视图渲染协议补充.md)。

## 1. 首页布局（MD 风格三段式 + 悬浮按钮）

```
┌──────────────────────────────────────┐
│ 语法糖手册  V1.0        [文档] [设置]  │  ← 顶栏（标题 + 版本副标题 + 操作按钮）
├──────────────────────────────────────┤
│         估算血药浓度折线图              │  ← 上：Chart(line) 0..48h 浓度序列
│       ╱╲      ╱╲                      │
│      ╱  ╲____╱  ╲___                  │
├──────────────────────────────────────┤
│ ⚠ 不良反应：危险 · 代谢：危险           │  ← 中：预警栏（三级差异化着色）
│   恶心  权重 8                          │
│   CYP2D6  权重 5                        │
├──────────────────────────────────────┤
│ 氟伏沙明  100mg · 10-26 14:02          │  ← 下：药品列表（按最近服药时间从上到下）
│ …                                       │
│                        ╭───────────╮   │
│                        │ ＋ 服用药物 │   │  ← 右下悬浮圆角按钮（FAB）
                        ╰───────────╯
```

- **顶栏**：标题「语法糖手册」+ 淡色版本副标题「V1.0」；「文档」打开仓库主页（openUrl），「设置」打开应用系统设置页（openSettings）。
- **浓度折线图**：取 t28 引擎的浓度序列（`pk.seriesValues`），采样 0..48h、步长 4h，共 13 点；T½ 与生物利用度 F 从氟伏沙明资料库首个 pk 条目读取（无资料回退 T½=24h、F=1）。空台账（无服药记录）时展示演示剂量（100mg@0h + 100mg@24h）。
- **预警栏**：t28 引擎输出（`adrAlert` + `metabAlert` + `maxAlertLevel`），
  - 危险（3）：红底 #FDECEA / 红字 #B3261E
  - 警告（2）：橙底 #FFF3E0 / 橙字 #E65100
  - 提示（1）：蓝底 #E3F2FD / 蓝字 #1565C0
  - 无预警（0）：绿底 #E8F5E9 / 绿字 #2E7D32（「暂无联用预警」）
- **药品列表**：每条 = 药名 + 剂量(mg) + 时间（`fmtTime` 的 MM-dd HH:mm），按最近服药时间从上到下排列（台账最新在前）。无记录时显示占位文案。
- **悬浮按钮「服用药物」**：记录一次服药（药名取最近一条记录，空台账回退「氟伏沙明」；剂量 100mg；时间 `timeNow()`），写入 storage 键 `ledger`（core/json 序列化），随后刷新浓度曲线、药品列表与预警栏并弹 toast。

## 2. 数据与持久化约定

| 键 | 内容 | 序列化 |
| --- | --- | --- |
| `drugs` | 用户药库（t28） | core/json 数组，每元素一个 Drug |
| `ledger` | 服药台账（本任务新增） | core/json 数组，每元素 `{drug, amount, time}`（time 为 Unix 毫秒字符串） |

台账 `time` 字段按 drugs.subl 的 Nat 字段约定编码为 JSON **字符串**（`jsonLit(toStr(...))`），读取侧 `jsonNatField` 经 `parseNat` 还原。不使用分号/管道等手工编码。

## 3. 编译与桌面验证

前置：JDK（任意 17+ JRE 即可跑 CLI 编译）、Node.js。

```powershell
# CWD = 本仓库根目录（模块扫描/处理器按 CWD 相对加载）
java -cp "<主仓库 5 模块 jar>;<kotlin-stdlib.jar>" sugared.functor.MainKt compile app -o app/out.js

# 桌面断言（out.test.js = 在生成码闭包内注入桥 mock + 68 条断言）
node app/out.test.js      # 期望：PASSES=68 FAILS=0，退出码 0
```

断言覆盖（68 条）：
- 生命周期注册与布局桥调用、根视图树；
- 顶栏标题/版本/双按钮、图表 kind/color/13 点序列与**独立公式逐点重算一致**、X 轴刻度；
- 预警分级（危险 3）、差异化着色（levelBg/levelFg 全四级）、触发项文案（恶心 8 / CYP2D6 5）；
- 悬浮按钮属性（主色/圆角/回调 id 注册）；
- 台账 core/json 往返、48h 滑动窗口换算（超窗过滤、空台账回退演示剂量）、保序去重的最近药品排序、行文本格式；
- **FAB 点击端到端**：记录 → storagePut → 列表/曲线刷新 → 二次点击台账 2 条且时间降序；
- 文档/设置意图（openUrl）、t28 引擎回归（summaryLine、共享反应权重、酶抑制权重、药代字段、doseEffect 三点）。

## 4. 端到端 APK 构建（-A 注解处理器链路）

前置：`JAVA_HOME` 指向 JDK 17（`F:\jdk-17.0.13.11-hotspot`），sdk-lite 解压目录可访问（`F:\SublimationProject\sublimation for android\sdk-lite`）。

```powershell
$env:JAVA_HOME = 'F:\jdk-17.0.13.11-hotspot'
java -cp "<主仓库 5 模块 jar>;<kotlin-stdlib.jar>" sugared.functor.MainKt compile app -o app/out.js `
  -A appDir="F:\SublimationProject\Sugar-Manual\android-app" `
  -A jsPath="F:\SublimationProject\Sugar-Manual\app\out.js" `
  -A sdkDir="F:\SublimationProject\sublimation for android\sdk-lite" `
  -A outDir="F:\SublimationProject\Sugar-Manual\build-apk"
```

- **-A 选项必须给绝对路径**（否则 E-PROCESSOR-SCRIPT）。
- 处理器（`annotation processer/android.subs`）调用宿主能力 `buildAndroidApk`：
  1. 把 JS 产物拷进 `android-app/app/src/main/assets/app.js`（附加 `__dshBoot()` 引导与 `main()` 调用尾）；
  2. 运行 sdk-lite 的无 Gradle 构建脚本（aapt2 compile/link → d8 → zipalign → apksigner，debug 密钥签名）；
  3. 产物：`<outDir>/app-debug.apk`。
- 验收实况（2026-10-26）：编译 exit=0；APK 5.58MB、804 条 zip 条目、`assets/app.js` 71354 字节，含 `Chart("line"...)`/`FloatingButton(...)` 视图构造、saveLedger/loadLedger 与 storagePut/storageGet 桥调用、顶栏与预警着色字符串；`jarsigner -verify` 通过（jar 已验证）。

## 5. 已知限制

- 语言的算术表达式**不含乘优先于加的优先级**：`acc + a * b` 会生成 `((acc + a) * b)`（编译器输出 H-ARITH-PRECEDENCE 提示）。涉及混合算术时必须显式括号（本仓库 `pk.concentrationAt` 已加括号修复）。
- `core_collection__distinct` 会**排序**而非保序去重；需要保序去重时手写 fold（见 `ledger.recentDrugs`）。
- 尾随 lambda 体内不能 `var` 声明；ANF 参数阴影；模块扫描不递归——详见 README「已知语言/编译器限制」。
