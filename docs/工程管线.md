# 糖手册工程管线 wiki

> 本 wiki 记录 Sugar-Manual（糖手册）从 .subl 源码到 JS 等价链测试与 Android 原生包的全链工程管线，
> 以及管线中实测确认的约束与折中。所有结论均以本仓库实际运行（runcompile / driver 等价链 / v2-assert /
> gradle / 设备实测）为依据，未经验证的方法论一律标「未验证」。
>
> 维护口径：改管线行为时同步改本页；改代码不改管线时无需动本页。

## 0. 管线全景

```
app/*.subl（含 @compose 视图与 JS 逻辑同源）
   │
   ├────────────────────────── JS 等价链（逻辑真相源）
   │     runcompile.bat → app/out.js + out/*.kt
   │     node app/build-test.js → app/out.test.js
   │     node app/out.test.js → sm-result.txt（PASSES= / FAILS=）
   │     node app/v2-assert.js  → 独立视图协议断言
   │
   └────────────────────────── @compose 原生通路
         out/Home.kt …（home.subl → 处理器生成的 Kotlin）
              │
         node android-app/tools/sync-gen.js（幂等补丁管线）
              │
         gen/（android-app/app/src/main/java/functor/sublimation/android/gen/）
              │
         runbuild.bat（gradlew assembleDebug --offline）
              │
         app-debug.apk（设备间接/装机验证）
```

设计要点：**同一份 .subl 源码驱动两条渲染通路**——JS 侧（`content()` 的 Dsh 视图树）与 @compose 侧
（`home.subl` → `out/Home.kt` → `gen/`），宿主 Kotlin（`DshComposeHost.kt`）以路由槽（`act`/`actText`/
`strArg`/`boolArg`）承载交互态，与 JS 同语义、storage 同源（ledger 写同一 SharedPreferences）。
JS 等价链是逻辑真相源：原生侧的交互语义先在 JS 断言里定义清楚，再在宿主镜像，最后靠 sync-gen 落盘。

## 1. 编译链：runcompile.bat

- 作用：subl → `app/out.js`（JS 等价链运行时）+ `out/*.kt`（@compose 生成物，含 Home.kt、PickerRowsA-C.kt、
  LibRowsA-D.kt、GeneratedCompose.kt 等）。
- 成功口径：输出末行 `EXIT=0`。错误形如 `[错误][行:列] E-UNBOUND-NAME`，语义检查失败时不会生成产物。
- **subl 语言陷阱**（编译期会拦，但不熟会绕路）：
  - 无 early return；`= return x` / `= { … }` 的块体写法非法——局部变量与返回值要写成
    `fun f(): T { var x: T = …; return … }`。
  - `*` 绑定优先级**低于**比较运算符，`dose >= typ * 4.0` 必须写成 `dose >= (typ * 4.0)`。
  - 纯函数内调用副作用函数需 `unchecked` 包裹（如 `unchecked var q: Str = pickQuery()`）；存储与刷新函数标 `@impure`。
  - 内建 `ceil` 是 Rat → Nat 的转换（`n = ceil(toRat(to - from) / step)`），无 `natOfRat` 之类内建。
- 运行环境注意：本机 Node 不在 cmd 默认 PATH 上，从脚本/进程拉起 node 时需
  `PATH=C:\\Program Files\\nodejs;C:\\Windows\\System32`。

## 2. 测试分层：v2 协议断言 + driver 等价链

两层都只依赖 `out.js`（不依赖设备与 gradle），但**桩与定位不同**：

| | driver-tail 等价链 | v2-assert |
|---|---|---|
| 载体 | `app/build-test.js` 聚合各 driver 文件 → `app/out.test.js` → 写 `sm-result.txt` | 单文件 `node app/v2-assert.js` |
| 定位 | 端到端「用户操作等价链」：触发生命周期、点 FAB、选药、输剂量、确认/取消、开抽屉、读 ledger/storage | 视图协议形态守卫：modifiers 链顺序/精确值、分区像素、实例键互异、布局一次 |
| 桩 | 驱动级全局（`__smLayouts`/ `__smStore`/ `__smLastToast`） | 独立 `__dshAndroid` 桩（storage Map、layout 捕获 caps、toasts、屏参 1080×2400/420dpi） |
| 句柄 | `__smA(name, cond, extra)` 计数；`__smCall(node, "onClick", arg)` 按 `__dshFn_<id>` 路由键回调；`__smNodes(root)`/ `__smRoot()`/ `__smHasText` | `check(name, ok, detail)`；`callKey(node.onClick)`；`latestTree()`；`eq()`/`mods()` |
| 结果 | `sm-result.txt` 首行 `PASSES=n FAILS=m` | stdout 末行 `PASSES=… FAILS=…` |

### 2.1 分层原则

1. **L1 纯函数断言**（模型/引擎，如 `seriesValues` 峰形、`packInfoOf` 权重、毒理教科书成员集）——driver 与 v2 都可直接调 `out.js` 暴露的函数，不渲染。
2. **L2 driver 等价链**——模拟用户操作序列，断言布局刷新次数、storage 落键、toast、抽屉显隐、曲线序列与交互态（如 t80 点卡高亮 toggle）。
3. **L3 v2 协议守卫**——锁死视图协议形态（链顺序、分区比例、实例键、刻度疏化），防止等价链「语义对但形态漂」。
4. **L4 设备验证**——`am start` 无 FATAL + 关键页面 uiautomator/手测；当前设备掉线并按队长指令停设备操作，以「装机间接验证」（L1-L3 全绿 + 宿主编译链通过）为验收口径。

### 2.2 回归迁移注意

等价链里大量断言**依赖采样网格**（点数与索引）。改采样步长这类「格式」级变更必须全链迁移：
- t81 把步长从 4h 改为 10min 后，`Chart` 采样点 13 → 289，末点索引 12 → 288，`pt24` 索引 6 → 144，
  v2 的 `labels.length` 13 → 289（可见刻度仍 5 个）。**断言先迁移再跑**，否则会把正确的实现误判为回归。

## 3. @compose 原生通路与 sync-gen 幂等补丁管线

### 3.1 为什么需要补丁管线

`home.subl` 经 @compose 处理器生成的 `out/Home.kt` 不能直接覆盖 `gen/Home.kt`：

- 视图树里的列表段（效应标签流、效应包详情）由宿主运行时计算，生成物只留占位标记（`EFFECTTAGS_HOST`、`PACKSHEET_HOST`）；
- 宿主槽函数的下标参数（`strArg("profName", 0)` 形式）发射器不自动带上；
- t79 起抽屉换用宿主自绘 `DshSheet`，需把生成物里的 `ModalBottomSheet(…)` 调用替换掉。

`android-app/tools/sync-gen.js` 就是这个**幂等补丁器**，固定在 runcompile 之后执行。

### 3.2 补丁内容（顺序敏感）

1. **标记替换**：`EFFECTTAGS_HOST` → `DshComposeHost.Subl_EffectTags(...)`；`PACKSHEET_HOST` → `DshComposeHost.Subl_PackSheet()`。
2. **strArg 下标注入**：`strArg("profName")` / `strArg("sexName")` 等按出现顺序注入槽位下标。**必须用字面量
   split/join 替换**——`new RegExp('strArg("profName")')` 里的括号会被当成分组，静默匹配 0 处。
3. **5 处 `ModalBottomSheet(…)` → `DshSheet(onDismiss = …)`**：同样用字面量 split/join；正则转义在模板字符串里
   会被二次转义（`\\(` 折叠成 `\(` 产生「Unterminated group」）。其中**服药表单抽屉（cancelForm）单独注入
   `sheetFraction = 2f / 3f`**（用户要求：抽屉上沿拉到屏幕顶部下方 1/3 处——见 §5.2），其余 4 个抽屉保持默认（包裹内容）。
4. **逐字复制** ` PickerRowsA/B/C.kt`、`LibRowsA/B/C/D.kt`、`GeneratedCompose.kt`（列表拆分块，见 §6）。

### 3.3 幂等性与执行顺序

- 标准顺序：`runcompile.bat` → `node android-app/tools/sync-gen.js` → `runbuild.bat`。
- 幂等验证：sync 后备份 `gen/Home.kt`，重跑一次 runcompile 再 sync，两份字节一致即幂等（本管线已验证，
  仅注释缩进级别偶有差异需重落盘对齐）。
- 补丁器对「out 退化」是脆弱点：若 home.subl 结构大改（BottomSheet 调用形态、标记位置变化），
  sync-gen 的字符串锚点需同步更新——**改 home.subl 后先跑 runcompile 检查 out/Home.kt 的发射形态是否仍匹配锚点**。

### 3.4 路径口径

- `in scope` 申报路径写 `android-app/gen/Home.kt`，**实际落盘目录**是
  `android-app/app/src/main/java/functor/sublimation/android/gen/`（`DshComposeHost.kt` 在其上一层
  `…/android/`）。现状如此，wiki 以实际路径为准。

## 4. @compose 发射器约束：backgroundColor 只接字面量（实测结论与折中）

**实测结论（本会话验证）**：@compose 处理器在生成 Kotlin 时，`Card`/`Box` 等组件的 `backgroundColor`
参数**只接受字面量颜色名**。两种动态写法都被**静默丢弃**（不报错、不生成）

- `backgroundColor = cardBgOf(0)`（自由函数调用，发射器整体不生成该参数）

- `backgroundColor = if (chartHi() == name0()) "primaryContainer" else "surfaceVariant"`（if 表达式）。

**对照（同样是自由函数调用，能正常发射的参数）**：

- `Text(text = name0())` → `Text(text = DshComposeHost.strArg("name0"))`（0 参自由函数 === 整个参数表达式 → strArg 路由）；
- `visible = pickRowVisible(0)` / `visible = cardHiOf(k)` → `if (DshComposeHost.boolArg("pickRowVisible", 0))`（单字面量参数的 Bool 函数 → boolArg 路由）；
- 自由函数带**变量名参数**（如 `openDocFor(c.name)`）在 JS 侧可按闭包路由键执行；@compose 侧发射为 `act("openDocFor", listOf(k))` 的**字面量下标**形式。

**折中方案（t80 实例）**：需要「选中卡背景随状态变化」时，宿主侧不要走 backgroundColor，改用
`Box(modifier = paddingH(8), visible = cardHiOf(k)) { Text("● 高亮", ...) }` —— 用 boolArg 路由的 visible 承载选中态
（对应宿主 `boolArg` 路由 `cardHiOf`）；JS 侧无此限制（Dsh 运行时直接求值 if 表达式），JS 侧用
`backgroundColor = if (hiOn) "primaryContainer" else "surfaceVariant"`。两侧语义一致，形态不同。

**排坑方法**：对发射器未知语义的参数，先写最小探针（home.subl 里加一行），runcompile 后读 `out/Home.kt`
确认生成形态再决定写法——**生成物才是 ground truth**，文档规格可能滞后于处理器实现。

## 5. M3 ModalBottomSheet 互斥根因与 DshSheet

### 5.1 互斥根因（M3 1.3.1，设备实测）

需求：抽屉**禁下滑收回**（只能点遮罩/点外面退出），两种配置实测：

| 配置 | 下滑收回 | 点遮罩退出 | 系统返回 |
|---|---|---|---|
| `rememberModalBottomSheetState(skipPartiallyExpanded = true, confirmValueChange = { it != SheetValue.Hidden })` | ✅ 拦截 | ❌ **一并废掉**（act 路由无日志，未触发 onDismiss 整条回调链） | ✅ 仍可用 |
| `rememberModalBottomSheetState(skipPartiallyExpanded = true)`（无 confirmValueChange） | ❌ 会收回 | ✅ 正常（act: cancelForm） | ✅ |

根因：M3 的 dismiss 路径是「动画值 → Hidden 目标」；`confirmValueChange` 拦截 **Hidden 目标本身**，
导致「点遮罩 → hide() → 完成 → onDismiss」整条路径被一并拦截（下滑与点遮罩共用同一个值变化通道）。
`javap` 查 `ModalBottomSheetProperties` 只有 `(securePolicy, shouldDismissOnBackPress)`，**没有**
`shouldDismissOnClickOutside` 这样可单独关闭外点退出的开关——**在 ModalBottomSheet 上无法兼得**。

### 5.2 DshSheet（宿主自绘，t79 起）

放弃 ModalBottomSheet，改用全屏 `androidx.compose.ui.window.Dialog` 自绘：

```kotlin
@Composable
fun DshSheet(onDismiss: () -> Unit, sheetFraction: Float = 0f, content: @Composable () -> Unit) {
    val sheetInteraction = remember { MutableInteractionSource() }
    // sheetFraction：抽屉最小高度占屏高比例（0 = 包裹内容）；「拉到顶上 1:3 处」→ 2/3（用户口径）
    val sheetMinH = if (sheetFraction > 0f) LocalConfiguration.current.screenHeightDp.dp.times(sheetFraction) else 0.dp
    Dialog(onDismissRequest = onDismiss,
        properties = DialogProperties(usePlatformDefaultWidth = false)) {
        Box(modifier = Modifier.fillMaxSize().background(Color.Black.copy(alpha = 0.55f)).clickable(
            interactionSource = remember { MutableInteractionSource() }, indication = null, onClick = onDismiss)) {
            Column(modifier = Modifier.align(Alignment.BottomCenter).fillMaxWidth()
                .heightIn(min = sheetMinH)
                .clip(RoundedCornerShape(topStart = 16.dp, topEnd = 16.dp))
                .background(MaterialTheme.colorScheme.surface).imePadding()
                .clickable(interactionSource = sheetInteraction, indication = null) { }) { content() }
        }
    }
}
```

- 自绘半透明遮罩（`Color.Black.copy(0.32f)`，用户口径「稍稍变暗」）Box.clickable → onDismiss（点遮罩退出）；
  **遮罩高度必须用 `requiredHeight(screenHeight)`**：Dialog 窗口按内容 wrap_content，`fillMaxSize` 拿不到全屏高度、遮罩只盖到抽屉顶部（抽屉上方既不变暗也不响应点击——即「没有阴影、关不上」现象）；`fillMaxWidth().requiredHeight(fullH)` 强制窗口 wrap 到整屏高度后铺满。
- 抽屉本体 Column：`heightIn(min = sheetMinH)`（`sheetFraction > 0` 时取屏高比例作最小高度，内容更高仍撑开）+ `clip` 顶部 16dp 圆角 + `imePadding()` + 空击吸收的 no-op clickable（防点穿）；
- **全抽屉零拖拽手势** → 下滑不收回；系统返回走 Dialog 的 onDismissRequest；
- 外观与 ModalBottomSheet 一致（顶部圆角、遮罩），行为符合需求。
- **抽屉高度**：默认包裹内容；服药表单抽屉按用户口径「拉到顶上 1:3 处」注入 `sheetFraction = 2f/3f`
  （抽屉上沿在屏幕顶部下方 1/3 处，最小高 2/3 屏高；内容更高时 heightIn 不封顶仍自然撑开）。其余抽屉保持包裹内容。

### 5.3 已知的坑（避免重蹈）

1. **不要把 sheet 挂在外层 `Column` 里当覆盖层**：`fillMaxSize` 在 Column 里只拿到剩余空间，
   遮罩够不到全屏（sheet 上方的区域仍在响应主页内容）。必须用全屏 `Dialog`（`usePlatformDefaultWidth = false`）。
2. gen 里的 sheet 调用形如 `DshSheet(onDismiss = { DshComposeHost.act("cancelForm") })`——
   生成物里仍是 `ModalBottomSheet` 由 sync-gen 统一替换（§3）。

## 6. 已确认的工程约束清单

- **Compose 单方法 64KB 上限**：home.subl 的选药/药库列表内联曾触发 `MethodTooLargeException`（124 行内联）。
  折中：拆为 7 个 @compose 块（`PickerRowsA/B/C`、`LibRowsA/B/C/D`），由 sync-gen 逐字复制到 gen/。
- **宿主路由槽协议**（`DshComposeHost`）：
  - `act(name, args)`：UI 动作（toggleForm / pickDrugAt / commitDose / toggleChartHi / openPack …）；
  - `actText(name, v)`：TextField 回调（setDose / setPickQuery / setProfileAgeText …）；
  - `strArg(name)`：字符串读取槽（name_k / dose_k / time_k 记录卡槽、docName、chartHi…，`cardBgOf` 等带下标变体）；
  - `boolArg(name)`：布尔读取槽（isFormOpen / hasRec / isSel / pickRowVisible / cardHiOf …）。
  - 加新交互时四槽同步登记，未登记路由打 `Log.w`。
- **storage 键约定**：`ledger`（台账 JSON）、`sm_` 前缀的界面态键（sm_form / sm_pick / sm_dose / sm_err /
  sm_pickq / sm_charthi / sm_conds / sm_age / sm_sex …）。会话态（如曲线高亮）走 storage KV 跨 layout 重渲染，
  不随 ledger 持久化；宿主侧对应 in-memory `mutableStateOf`。
- **CJK 输入**：本测试设备不能经 adb 直接输入中文，CJK 交互态用 `storage` 注入或代码内构造断言验证。
- **Node PATH**：`PATH=C:\\Program Files\\nodejs;C:\\Windows\\System32`（脚本拉起 node 时）。
- **adb**：`F:\\AndroidSDK\\platform-tools\\adb.exe`；当前设备掉线且按队长指令停设备操作，验收以
  L1-L3 全绿 + 宿主编译链（runbuild）为口径。
- **禁止 git commit/push**：统一由队长执行；跨任务的同步文件（driver-tail.js / v2-assert.js / gen 副产物）
  记录在任务输出中、不在 changedPaths 申报。

## 7. 常用命令速查（工作目录 = Sugar-Manual 根）

```bat
:: 1. 编译（subl → out.js + out/*.kt）
runcompile.bat

:: 2. 原生侧落盘（幂等补丁）
node android-app\tools\sync-gen.js

:: 3. 构建包
runbuild.bat

:: 4. JS 等价链（driver 链）
node app\build-test.js && node app\out.test.js      :: 写 sm-result.txt

:: 5. v2 视图协议断言
node app\v2-assert.js

:: 6. 幂等性自检（可选）
::   备份 gen/Home.kt → 重跑 runcompile → 重跑 sync-gen → 字节比对
```

验收口径（实现类任务，以 t80/t81 为例）：`runcompile EXIT=0` + driver 链 `PASSES=n FAILS=0` +
`v2 PASSES=m FAILS=0` + sync-gen 幂等 + `runbuild BUILD SUCCESSFUL`；装机验证在设备可用时补做，
当前以 L1-L3 全绿作装机间接验证。

- 管线行为变更（sync-gen 锚点、发射器约束、路由槽、键约定、构建命令）→ 同步改本页。
