# 渲染层能力差距清单（Sublimation 视图协议 vs Kotlin Compose 参考实现）

> **来源**：t52 照 F:\KotlinProject\Sugar Manual（原生 Compose/M3 工程）逐屏翻译
> F:\SublimationProject\Sugar-Manual\app\main.subl 时，逐条比对 Compose 布局特性与当前
> Sublimation 视图协议（@view 结构体 → layout 桥 JSON → DshBridge.kt 渲染分支）的表达能力。
> **这是 SfA 布局表达力不足的定案证据，也是后续扩视图协议的需求来源。**
>
> 参考实现涉及文件：ui/HomeScreen.kt、ui/DoseLogList.kt、ui/InteractionAlerts.kt、
> ui/DoseEntrySheet.kt、ui/ConcentrationChart.kt、MainActivity.kt、ui/Theme.kt。

## 0. 结论速览

| 类别 | 条目 | 判定 |

## 1. Modifier 系统：无链式组合（❌ 核心缺口）

**Compose**：Modifier.fillMaxWidth().padding(horizontal = 24.dp, vertical = 8.dp).height(20.dp)——修饰符链、方向化 padding、比例尺寸、weight 弹性分配。

**当前协议**：Modifier 是单字段 enum（Plain/FillMaxSize/WrapContent/Padding(Nat)/Width(Nat)/Height(Nat)/Center），一个视图只能带**一个**。

撞上的具体例子（DoseLogList.kt 的药名颜色竖条）：

```kotlin
Box(modifier = Modifier.width(4.dp).height(20.dp).background(barColor))
```

**翻译失败现场**：Box(modifier = Width(4), Height(20), ...) 直接**编译错误**（期望ASSIGN）；拆成两个嵌套 Box 也不成立——外层 Width(4) 的内层 Box 高度只能靠内含 Text 的行高凑。最终近似写法：

```subl
// 竖条：Width(4) 定宽 + 内含 Text 撑出文本行高（高度随字号，非精确 20dp）
Box(modifier = Width(4), backgroundColor = bar) { Text(text = " ", size = 14) }
```

**差距性质**：结构性——不是「少个圆角」的程度，而是「一个视图不能同时表述宽和高」。任何固定宽×高的装饰块（竖条、色点、图例点）都无法精确表达。

**建议扩展**：Padding 四方向重载、Size(宽,高)、FillWidth/FillHeight（比例）；中期把 Modifier 改成可拼接链。

## 2. 无 fillMaxWidth / weight（❌）

**Compose**：LazyColumn(Modifier.fillMaxWidth().weight(1f))；Text(Modifier.weight(1f)) 把剂量顶到行尾。

**当前协议**：Width(n) 只能写死像素（本仓用 screenWidth() 量屏后传参变相约等于 fillMaxWidth）；weight 完全不存在——线性容器内子视图不能弹性分配空间。

**翻译近似**：
- 记录卡全宽：Box(modifier = Width(cardWidth(sw)))，cardWidth(sw) = sw - 48（把 Compose 的 padding(horizontal=24)+fillMaxWidth 手算成像素差）。
- 剂量顶到行尾：做不到，只能 "   " 空格 Text 拉开距离。

**差距性质**：响应式布局缺失——旋转屏/不同屏宽需手算像素。

**建议扩展**：FillWidth（MATCH_PARENT 宽）、Weight(Nat)（线性内弹性）。

## 3. 无方向化 Padding / 无 Arrangement 间距（❌）

**Compose**：padding(horizontal = 24.dp, vertical = 8.dp)；Arrangement.spacedBy(8.dp)；Arrangement.SpaceBetween（图例左、徽标右两端对齐）。

**当前协议**：Padding(Nat) 四边同值（KT 端 view.setPadding(p,p,p,p)）；容器无 spacing/arrangement 概念，contentAlignment 仅 7 档 Gravity。

**翻译近似**：标签间距 " " Text 占位；卡片/上下间隔用空 Box(modifier = Height(n))；padding(h24,v8) 近似为 Padding(24)（按水平边距对齐，垂直边距牺牲）。

**建议扩展**：Padding(Nat,Nat,Nat,Nat)；Box 加 spacing/arrangement 字段。

## 4. ModalBottomSheet / AlertDialog / 弹出层（❌ 完全无）

**Compose**：ModalBottomSheet（底部抽屉，遮罩+圆角+滑动关闭）、AlertDialog（设置/文档弹窗）。

**当前协议**：无 Dialog、无 BottomSheet、无蒙层、无弹出层渲染分支。t47/t52 均以**页内面板**替代：FAB 点击切换 storage KV 开关 → layout(content) 整树差量刷新 → 表单作为页面内联区块出现。

**差距性质**：模态语义无法表达（抽屉浮于内容之上、点遮罩/滑动关闭），表单是「挤进页面流」而非「覆盖页面」——视觉与交互都不同。

**建议扩展**：新增 Dialog/BottomSheet 视图（含 dim 背景、dismiss 回调）。

## 5. 无 TopAppBar/Scaffold/导航（❌）

**Compose**：Scaffold(topBar=…, floatingActionButton=…)、TopAppBar(title, actions, colors)、MainActivity 的 Page 路由 + BackHandler。

**当前协议**：顶栏 = 手摆横向 Box + 三个 Button；「药物」按钮只能 toast 说明无多页导航；无导航栈/返回键处理。

**近似写法**（本仓 topBar）：薄荷绿底（backgroundColor = #B2DFDB）+ 标题行 + actions；actions 的右推（SpaceBetween）做不到，按流式排布。

**建议扩展**：TopAppBar 视图 or 容器 arrangement；页面导航协议（可用多 layout 画面 + storage 画面态近似，但无返回键）。

## 6. 列表项点击分辨不了来源行（❌ 交互层关键缺口）

**Compose**：items(DrugCatalog.all) { drug -> Surface(onClick = { selectedDrug = drug }) }——每个列表项都有独立点击处理。

**当前协议**：onClick 的回调 id 由**源码构造点**编号（如 Button_onClick_7），运行时 globalThis.__dshFn_<id> 是**单一全局槽**。递归/循环生成的同款按钮把闭包反复写入同一槽位——**只有最后构造的那行活着，前面全被覆盖**。

**验证**：本仓药物行最初写成递归 drugRows，结果点「氟伏沙明」行实际选中「帕罗西汀」（最后一行）。t47 的断言恰好点的是最后一行（帕罗西汀），侥幸通过。

**近似写法**：把列表**在源码里展开成 N 个独立函数**（drugRow0…drugRow3），一药一个构造点：

```subl
@composable
fun drugRow1(drugs: List[Drug], idx: Nat, sel: Bool): Any = when (elementAt(drugs, 1)) {
    is Some(d) => Box(modifier = Plain()) {
        Button(onClick = { unchecked pickDrug(1) }) { Text(text = rowText(d, 1, idx, sel), ...) }
    }
    None => Box(modifier = Plain()) {}
}
```

固定 4 行能跑，但**动态长度列表无法实现**（行数必须在源码里写死）。

**建议扩展**：回调 id 按**构造实例**编号（运行时自增），或提供带参回调（onClick 传回 item index/任意 JSON 值）。

## 7. 容器无 onClick / Button 是叶子（❌）

**Compose**：整行可点击的 Surface(onClick = …)；按钮内可放任意组合。

**当前协议**：Box 等容器无 onClick；Button 是叶子——KT 端 buildButton 只从 body 提取**首个直接 Text** 作文案（extractText），body 里的 Box 等子视图**不渲染**。

**翻译近似**：参考的「圆角选择条（两行文字）」压成单个 Button 单 Text：文案 = 药名\n副标题（rowText），选中态 ✓ 前缀 + bold；参考的选中底色变化做不到（Button 无背景/形状字段）。

**建议扩展**：Box 加 onClick（或新 Clickable 容器）；Button 透传子视图。

## 8. 无半透明色 / 无主题色系统（❌）

**Compose**：Color(0x33D32F2F)（20% 透明红底）；MaterialTheme.colorScheme.primary。

**当前协议**：颜色仅 #RRGGBB（KT 端 parseColor 不含 alpha）。无主题/暗色模式概念。

**翻译近似**：按 0x33≈20% 与白底**预混**成实色并硬编码（tagBg）：

| 参考半透明 | 预混实色 | 文字色 |
| --- | --- | --- |
| 0x33D32F2F（危险底） | #F6D5D5 | #C62828 |
| 0x33F9A825（警告底） | #FEEED3 | #E65100 |
| 0x334CAF50（提示底） | #DBEFDC | #2E7D32 |

**建议扩展**：#AARRGGBB 或颜色字面加 alpha 字段；主题色表（primary/onPrimary/…）。

## 9. 无动画（❌）

**Compose**：过量反应标签 rememberInfiniteTransition + animateFloat 做 1.0↔0.25 透明度闪烁（AlertTag 的 flash）。

**当前协议**：无动画、无过渡、无状态驱动的时间变化。闪烁**只能在文案上区分**（flash 项与危险级同色处理）。

**建议扩展**：简单时间线动画协议（透明度循环）。

## 10. 图表：单序列（❌ 多序列/图例/渐变）

**Compose**（ConcentrationChart.kt）：Canvas 自绘——每种药一条各自颜色的分量线 + 一条总浓度主线 + 垂直渐变填充 + 左上角图例（色点+药名）+ 右侧「估算」徽标 + 网格/双轴刻度。

**当前协议**：Chart（kind = line|bar）只有单序列 points/labels/color——单色、无图例、无多线、无渐变。

**翻译近似**：只保留总浓度单线（色 #00695C），分量线与图例**丢弃**。

**建议扩展**：Chart 支持 List[Series]（每序列 points+color+label）；渐变填充。

## 11. 文本/输入表达力（⚠️）

| Compose | 当前 | 判定 |
| --- | --- | --- |
| Text 多样式 Span、labelSmall/titleLarge 字号阶 | 整体 size/bold/italic/maxLines | ⚠️ 近似 |
| OutlinedTextField(label, isError, supportingText, singleLine) | TextField(placeholder, text, keyboard) | ⚠️（label→placeholder，错误提示→toast） |
| TextButton（无边框）/ Button（填充） | Button 单一 MaterialButton 样式 | ⚠️ 无样式变体 |
| Icon(Icons.Filled.Add) | 无图标视图（FAB 无图标槽） | ❌ |

## 12. 无 FlowRow 自动换行（❌）

**Compose**：预警标签 FlowRow(spacedBy 8.dp)——宽度不够自动换行，全部混排。

**当前协议**：横向 Box(scrollable = true) = 单行横滚，**不换行**。

**翻译近似**：单行横滚（alertStream），标签按等级降序混排（alertItems），仅靠颜色分级、无组标题——信息架构与参考一致，换行降级为滚动。

**建议扩展**：容器 wrap=true（FlexboxLayout 包装）。

## 13. 无 LazyColumn（⚠️）

**Compose**：LazyColumn 懒加载 + item{}/items() 粘性 + contentPadding(bottom = 96.dp)。

**当前协议**：Box(scrollable = true) = 整段 ScrollView，**全量渲染**；无 item 粒度、无 contentPadding（96dp 底部留白用末尾空 Box(Height(96)) 近似）。

**差距性质**：演示量级无碍；真实长列表无懒加载。

**建议扩展**：LazyColumn + item 集合协议。

## 14. 状态与重组（⚠️ 架构层差异）

**Compose**：remember{mutableStateOf} 局部状态、collectAsState 自动重组、ViewModel 持有。

**当前协议**：工程模式**顶层不允许 @mut var**（只允许声明）；整树刷新重建 content() 的局部状态 → 跨帧状态必须走 storage KV（本仓 sm_form/sm_pick/sm_dose），靠 layout 桥二次调用的 applyRootDiff 差量刷新。TextField onChange 只能写草稿、不触发重渲染（重建输入框丢焦点）。

**差距性质**：响应式细粒度重组缺失，任何局部 UI 状态都要持久化绕路。

## 附 A：本仓翻译的落地差异清单（main.subl vs Compose 参考）

2. 记录卡：Card(surfaceVariant) + 4dp 颜色竖条——底色 ✅（Box Width(sw-48) + #E7E0EC）、竖条 ⚠️（宽精确、高由 Text 行高近似）、圆角/阴影 ❌。
3. 顶栏：primaryContainer 薄荷绿 ✅、三按钮 ✅、SpaceBetween 右推 ❌。
