# 与原生版布局对照结论（t59 决定性验收）

> **任务**：t59 以 Kotlin 原生版（F:\KotlinProject\Sugar Manual，com.sugarmanual，Compose/M3）
> 为 1:1 参照，用 @view 通路 + v2 stdl（t54 交付）改写糖手册主界面，逐项核对布局保真。
> **本文是「SfA 渲染层能否复现 Compose 版糖手册」的定案结论。**

## 0. 结论速览

| 维度 | 判定 | 说明 |
| --- | --- | --- |
| 首页整体结构 | ✅ 一致 | Scaffold 四要素（顶栏/折线/滚动列表/FAB）+ 两弹层全部复现 |
| 比例分区（45/55） | ✅ 一致 | 图 45% + 下半区 55%，内容区 = 屏高 − 顶栏 64dp，**无 5% 空隙** |

| 卡片圆角/阴影 | ✅ 一致 | Card cornerRadius 12 + elevation 1 + surfaceVariant |
| 主题色 | ✅ 一致 | primaryContainer/onPrimaryContainer/surfaceVariant/onSurface/… 色名直传 |
| 半透明标签底 | ✅ 一致 | #AARRGGBB 直写参考原值（0x33D32F2F 等），不再预混 |
| 折线图 | ✅ 一致 | 多序列逐药分量线 + 总线逐点求和 + 图例 + 徽标 + 12h 刻度 |

| 文本色细节 | ⚠️ 近似 | TextButton 无 color 字段：actions 文字按主题 primary 而非 onPrimaryContainer |
| FAB 容器色 | ⚠️ 近似 | FloatingButton 单色 tint（primary）；参考为 primaryContainer+onPrimaryContainer |
| 输入框 | ⚠️ 近似 | OutlinedTextField 的 label/isError 仍无 → placeholder + toast 校验 |
| 懒加载 | ⚠️ 近似 | ScrollView 包装，无 LazyColumn 的按需合成 |
| 多页导航 | ❌ 缺 | 「药物」按钮只 toast（协议无 NavHost） |

**总判定**：除「多页导航」与若干纯文本/输入框细节外，首页布局结构与数值已与原生版逐项一致。
t52 判定的「布局紊乱」是 v1 协议的表达力缺口，**不是渲染层（DshBridge/原生 View）的缺陷**——
同一渲染层在 v2 协议输入下复现了参照布局。验收方式见 §6（编译/断言/APK 三关全绿）。

## 4. 仍存差距（诚实登记）

1. **TextButton 文字色**：协议无 color 字段；顶栏 actions 在 primaryContainer 底上应取
   onPrimaryContainer，实际渲染主题 primary。影响：深浅色对比可辨，色相不同。
2. **FAB 容器色**：FloatingButton 单色 tint（primary）；Material 规范为
   primaryContainer + onPrimaryContainer 前景。
3. **OutlinedTextField**：label/isError/单行错误文案仍无，以 placeholder + toast 校验近似
   （差距清单 ⚠️ 项，v2 未扩输入框）。
4. **LazyColumn 懒加载**：下半区/药物列表仍是 ScrollView 包装；首屏数据量小，视觉等价，
   差别在万行级合成的内存行为（@compose 生成物侧为真 LazyColumn）。
5. **多页导航**：「药物」按钮仅 toast（协议无 NavHost；差距清单 ❌ 项）。
6. **✓ 占位**：未选行用透明 ✓ 恒占布局位（等价布局，视图数比参照的条件渲染多 1 个 TextView/行）。
7. **同级标签顺序**：按等级分组而非完全权重降序（嗜睡 5 列在失眠 6 前）。
8. **Card padding 落点**：paddingV(6) 落在 CardView 自身（卡背景外延 6dp），Compose 的
   padding 在 Card 之外（间隙显页面底色）。视觉：卡片间距相同，间隙色不同。
9. **图表采样**：步长 4h（13 点）对参照 1h（49 点），刻度密度一致（每 12h），曲线折线化略明显。
10. **演示回退**：空台账给演示曲线/固定两药联用演示预警（SfA 端产品决策，参照空数据为空图空预警）。

## 5. children= 平铺技术（本轮关键工程发现）

v2 视图结构体的 children 字段由 @view 注入器加入（body 语句 → flat children）。对**动态列表**
（标签流、记录卡、选药行），递归函数若返回嵌套 Box 链（t52 写法），FlowLayout/ScrollView 只拿到
一个「链条」子级——换行失效、间距失效。t59 写法：

```subl
@composable
fun tagList(ts: List[Trigger], drugs: List[Drug]): List[Any] = when (ts) {
    Nil => emptyList()
    is Cons(t, rest) => cons(tagCell(t, drugs), tagList(rest, drugs))
    else => emptyList()
}
// 不写 body，显式传 children（写 body 会被重写为 children，与显式传值冲突）
Box(modifier = fillWidth(), wrap = true, spacing = 8, children = tagList(alertItems(adr), drugs))
```

要点：① 列表元素函数标注返回 Any（cons 类型推断 List[Any]）；② 容器**不带 body**，
否则 body 语句重写的 children 会覆盖显式传值（编译可过、运行丢清单）；③ 递归每行各自
构造视图 → __dshCb 实例键自然互异。断言 E/H 证明了平铺（children.length == 行数、
每个子级是标签/卡片本体而非中间容器）。
