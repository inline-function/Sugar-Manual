# 01 · 决策与路线图（2026-11-03，用户已批）

## 用户决策

1. **JS 真相源（彻底）**：目标态 = act 事件 callJs 进 WebView，JS 算完 pushState 回宿主渲染，宿主只剩桥。
2. **编译器/注解处理器改动须先汇报审核**：F:/KotlinProject/Sublimation 源码可读可改，
   但任何对编译器本体或 annotation processer/*.subs 的修改，**先报方案获批准再动手**。
3. **DSL 缺口协商制**：回迁中撞到 DSL 表达不了的（网格、长按、水波纹控制等），
   先写进 log/02-DSL缺口清单.md，找用户协商，不擅自扩 DSL。
4. 节奏：慢慢来，**每一步思路都写进 log 防失忆**；最终目标 app 目录只有 .subl。

## 三阶段路线

### Phase 1 · 数据回迁（药库/效应/包/递质 → subl）
- 宿主里写死的 103 种药表、效应表、包定义、递质模型，回迁为每药独立 .subl（照 app/碳酸锂.subl
  既有模式）+ warn.subl 扩展 + drugs.subl 入口。
- **验收**：runcompile EXIT=0；out.js 含全部药库；v2-assert / driver 等价链不回归；
  宿主逐块改为从此源镜像（宿主保留 Kotlin 镜像是管线既定设计，问题是不能只有宿主没有源）。
- 风险：纯数据、零 UI 风险。撞到 subl 语法陷阱先查 docs/工程管线.md §1。

### Phase 2 · 接线翻转（以日历页为试点）
- 日历是唯一"视图+交互+账本操作"全在宿主的页面，是最好的 JS 真相源试点：
  calOpen/calYear/calMonth/calSelDay 状态搬进 JS（storage 持久化 + pushState 推 6×7 网格数据），
  宿主只保留渲染（读 stateOf 槽位）与事件（act → callJs）。
- 预期 DSL 缺口：7×6 网格布局、长按手势、日期圆圈选中样式 → 记缺口、找用户协商。

### Phase 3 · 全面铺开 + 宿主瘦身
- 选药/剂量表单、购物篮 t90、包详情、图表、设置/文档……逐页按 Phase 2 模式翻转。
- 每翻一页：JS 等价链先写断言（driver 或 v2-assert）→ 宿主删镜像 → 设备验证。
- 收尾：宿主只剩桥（attach/pushState/callJs/storage/渲染槽），sync-gen 补丁尽量归零。
